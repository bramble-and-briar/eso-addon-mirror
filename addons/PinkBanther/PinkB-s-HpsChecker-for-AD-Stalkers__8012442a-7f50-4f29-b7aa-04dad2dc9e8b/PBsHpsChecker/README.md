# PB's HPS Checker

シロディールの PvP で、自分がどれだけ回復で貢献したかを数字で見られる Elder Scrolls Online 用アドオンです。

- 合計の回復量と **HPS**（1 秒あたりの回復量）
- **誰を回復したか**（プレイヤー名ごとの回復量と割合。名前は PSN ID で出ます。分かる範囲は「名前の表示」）
- **どのスキルで回復したか**
- 回復量のうち、**パーティーメンバー・パーティー外・自分自身**にそれぞれどれだけ行ったか（比率）
- **パーティーメンバーが受けた回復のうち、自分の分が何%か**（他のヒーラーの回復が届く場合。下の「まだ実機で確かめていないこと」）
- 戦闘ごとの履歴と、今日・今月・過去の日や月ごとの集計

ゲームが知らせる出来事を読むだけで、代わりにボタンを押したりスキルを使ったりすることはありません。

## 導入

`PBsHpsChecker` フォルダを ESO のアドオンフォルダに置きます。設定メニューには LibHarvensAddonSettings（20106 以上）が必要です。他の PB's アドオンと同じライブラリで、コンソールでも PC でも使えます。無くても記録と HUD メーターは動作し、`/hps` コマンドで集計を見られます。

## 使用できる人

このアドオンは、PSN ID が **PinkBanther** と **Yukiblack1123** の 2 つだけ使用できます。起動時にログイン中の PSN ID（`GetPlatformDisplayName()`）を読んで照合します。大文字小文字、先頭の `@`、性別の接尾辞は区別しません。アカウント名（@名）は見ません。

それ以外の方では、保存データ・画面・設定パネル・イベントの登録を何も作らず、ログイン後にチャットへ「あなたはこのアドオンを使用できません」と 1 行だけ出します（クライアントの言語に関係なく日本語です）。`/hps` を打つと同じ文と、読み取った PSN ID（`PSN ID: …`）が出るので、使えるはずの方が断られたときは、その行で原因が分かります。

これはアドオンの Lua を読める人には外せる、簡易の制限です。PB's TargetPlayer・Compass と同じ作りです。許可する ID を変えるときは `Main.lua` の `ALLOWED_USERS` を書き換えます。

## 見かた

### HUD メーター

回復を始めると、画面の左側に小さな枠が出ます。

```
HPS  8,420                          戦闘の HPS
直近10秒  9,100                      直近 10 秒の HPS
回復量  456,789   3:12   14人          合計・回復していた時間・回復した人数
パーティー 62%  パーティー外 31%  自分 7%    回復先の内訳
パーティーが受けた回復のうち自分の分  72%    パーティーメンバーが全ヒーラーから受けた回復の中の、自分の割合
```

5 行目は、その戦闘でパーティーメンバーを回復したときに出ます（誰も回復していないときは出ず、枠は 4 行の高さに戻ります）。他のヒーラーの回復が 1 つも届いていないときは、自分の回復がすべてなので 100% と出ます。

戦闘が終わると「戦闘終了」に変わり、設定した秒数（初期値 10 秒）だけ残ってから消えます。設定画面を開いている間は、位置を決められるようにサンプルの数字で表示します。

メーターの枠は、**幅と高さを px で指定**することもできます。設定画面の「枠の大きさをpxで指定する」をオンにすると、「枠の幅 (px)」と「枠の高さ (px)」のスライダー（5px 刻み、幅は 120〜画面の幅、高さは 60〜画面の高さ）の値ちょうどの枠になります。オンにした時点では今の枠の大きさから始まるので、枠が飛ぶことはありません。指定した大きさに文字が収まるかは問わないので、幅が足りない行は末尾が「…」で省略され、高さが足りないと下の行が枠の外にはみ出します。オフのときは、文字に合わせた大きさです（5 行ぶんで 200px 前後）。文字の大きさは、枠の大きさとは別に、次の「メーターの大きさ」で決めます。

メーターの大きさは、設定画面の「メーターの大きさ」で 1（最小）〜 7（最大）から選びます。標準は 4 です。文字の大きさが段階的に変わり、枠も合わせて広がります。滑らかな拡大ではなく段階式なのは、コンソールが読み込み済みの名前付きフォント（20〜34 番）だけを使うためです（読み込まれていない文字を作ると、PS5 でアドオンが落ちた例があります）。そのため、7 より大きくはできません。設定画面を開いている間は、メーターがサンプルの数字で出るので、大きさと位置をその場で見ながら決められます。

### 統計画面（メインメニュー）

メインメニュー（ゲームパッドのメニュー）に、**「ヒール統計」**の項目があります。**「ステータス超詳細」（PB's Ultra Detailed Stats）の次**に入ります（ステータス超詳細が無いときは、キャラクターの次です）。選ぶと、画面の中央に、**背景が透けない**統計画面が開きます。設定 > アドオン > PB's HPS Checker の「統計画面」ボタン、または `/hps stats` からも開けます。

画面は 3 ページです。ページの名前は、右上に並びます（今のページがピンクです）。

| ページ | 内容 |
| --- | --- |
| 統計 | 1 つの**期間**の統計。4 つのブロックを並べます（下の表） |
| 期間の一覧 | **過去の履歴**の目次。今日・今月・全期間・過去の月・過去の日（保存されている 60 日ぶんすべて）を 1 行ずつ並べ、それぞれの回復量・HPS・戦闘回数・回復時間・回復先の比率・「受けた回復のうち自分の分」を出します。選んで A を押すと、その期間の統計が開きます |
| 戦闘の履歴 | 最新 40 戦。日時・時間・HPS・回復量・回復した人数・パーティーへの比率・いちばん回復した相手 |

「統計」ページの 4 つのブロックは次のとおりです。

| ブロック | 内容 |
| --- | --- |
| 概要 | 回復量、HPS、戦闘回数と回復していた時間、最高の戦闘 HPS、最大の 1 回復、クリティカル率、オーバーヒール、**パーティーへ / パーティー外へ / 自分への比率と量**（パーティーとパーティー外は人数つき）、**パーティーが受けた回復のうち自分の分** |
| 回復した相手（**上位 10 人**） | 回復量・全体に占める割合。パーティーメンバーには `[PT 72%]` のようなタグが付きます。**見出しの `[PT n%]` は、このタグの読み方の凡例です（n は見本で、実際の数字ではありません）。** タグの % は、**その人が全ヒーラーから受けた回復の中の自分の割合** |
| 回復に使ったスキル（**上位 10 件**） | 回復量・全体に占める割合 |
| 直近の戦闘 | 最新 10 戦。日時・時間・HPS・回復量 |

操作は次のとおりです（画面の下のキーバインドの帯にも出ます）。矢印は帯に出ない代わりに、画面の一番下の 1 行に説明が出ます。

| 操作 | 内容 |
| --- | --- |
| LB / RB | 前 / 次のページ |
| ← → （十字キー・左スティック） | 「統計」ページ：前 / 次の期間（今日 → 今月 → 全期間 → 過去の月 → 過去の日 の順） |
| ↑ ↓ | 「期間の一覧」「戦闘の履歴」：行を選ぶ / スクロール |
| A | 「期間の一覧」：選んだ期間の統計を開く |
| X | 今日の統計に戻る |
| B | 戻る |

画面を開いている間は、数字が 2 秒ごとに更新されます。文字の大きさは、起こりうる最も長い行（大きな数字・長い名前）が列に収まる最大のサイズが、クライアントの測った文字幅で選ばれます。

### コマンド

| コマンド | 内容 |
| --- | --- |
| `/hps today` `/hps month` `/hps all` | 概要と、回復した相手・スキルの上位 10 をチャットに出す |
| `/hps stats [today\|month\|all]` | 統計画面を開く（期間を指定すると、その期間で開く） |
| `/hps hud` | HPS メーターの表示・非表示 |
| `/hps on` `/hps off` | 記録の開始・停止 |
| `/hps status` | ここまでに数えた回復イベントの数と、相手の種類ごとの内訳 |
| `/hps probe` | 2 分間、ゲームがアドオンに届ける回復を発生源・相手の種類ごとに数え、「他のヒーラー → パーティーメンバー」などが届いたかを ○/× で出す（計測用。もう一度打つと途中で止めて結果を出す） |
| `/hps debug` | 次の 200 回の回復を、ゲームが報告したままの値（相手の種類・回復量・overflow）で出す |

## 数え方

| 言葉 | 意味 |
| --- | --- |
| 回復 | 自分が発生源の回復・クリティカル回復・継続回復の 1 回分（4 種類のイベント） |
| 回復先の 3 区分 | イベントが持つ相手の種類で分けます。**グループのメンバー**=パーティー、**自分**=自分自身、**それ以外**=パーティー外 |
| 数えないもの | 自分のペット・コンパニオン・木人への回復 |
| 戦闘 | 最初の回復から、回復が途切れるまで。途切れ時間は設定（初期値 10 秒）。ゾーンの移動やログアウトでも終わります |
| 回復していた時間 | 戦闘の最初の回復から最後の回復まで ＋ 1 秒（回復が 1 回だけの戦闘で 0 秒割りにならないため） |
| HPS | 回復量 ÷ 回復していた時間。戦闘をまたぐ集計では、回復量の合計 ÷ 回復していた時間の合計 |
| 最高の戦闘 HPS | 10 秒以上続いた戦闘の中での最高値（1 発の大きな回復を「速さ」と呼ばないため） |
| 割合 | 3 区分の割合は回復量の合計を 100% とします。回復した相手の割合は、自分への回復を除いた合計に対するものです |
| 受けた回復のうち自分の分 | 自分がパーティーメンバーに行った回復 ÷（自分の回復 ＋ 他のヒーラーがそのメンバーに行った回復）。他のヒーラーには、パーティー外のヒーラーも、そのメンバー自身の自己回復も含みます。自分のペット・コンパニオンの回復は、どちらにも入れません。**他のヒーラーの回復が 1 つも届いていない間は、届いた分（自分の回復だけ）で数えるので 100% と表示します。** そのため、100% は「本当に全部自分だった」場合と「他のヒーラーの回復がアドオンに届いていない」場合の両方で出ます。どちらかは `/hps status` の `others > party members:` の行（届いた件数）で分かります。一部しか届かない場合も、実際より自分の割合が高く出ます。パーティーメンバーを誰も回復していない期間は、割合がないので「-」と表示します。メンバーごとの割合は、その人がパーティーにいたときの回復だけで計算します |
| 人数 | 概要の「パーティーメンバーへ」「パーティー外へ」に付く人数は、その期間に回復した、名前の違う人の数です。1 日に 60 人を超えて回復した日は一覧に残らない人がいるため、パーティー外の人数に `+` が付きます（「それ以上いる」の意味）。パーティーは多くても 20 数人で、回復量も大きいので、一覧から外れません |

日付は端末の時計（日本なら日本時間の 0 時）で切り替わります。

### 名前の表示（PSN ID）

「回復した相手」の名前は、PSN ID で表示します（設定の「ランキングの名前をPSN IDにする」、初期値オン）。ただし、回復のイベントがアドオンに運んでくるのは**キャラクター名だけ**なので、PSN ID は別の場所から覚えています。覚える場所は 3 つです。

| 覚える場所 | 何が分かるか |
| --- | --- |
| パーティーメンバー | 全員（ゲームが、メンバーの PSN ID と表示名を渡してくれます） |
| 照準を合わせたプレイヤー | 照準が乗っている間の、その 1 人 |
| キルフィード | 近くで倒した人・倒された人の両方。キルフィードの 1 行には、2 人ぶんの表示名とキャラクター名が入っています。ゲーム本体のキルフィードが PSN ID を出しているのは、この表示名をそのまま使っているからです |

この 3 つのどれにも当てはまらない相手（パーティー外で、照準を合わせたことがなく、キルフィードにも出ていない人）は、キャラクター名のままです。覚えた対応は保存され、あとで PSN ID が分かった相手は、それまでの記録も含めて PSN ID の表示に変わります（一覧が二重になることはありません）。

- PSN ID（プラットフォーム名）が無い相手は、ゲーム本体と同じく表示名（先頭の `@` は付けません）で出ます。どちらも無ければキャラクター名です。
- **同じ PSN ID で、キャラクター名が違う相手（キャラクターを複数持っている人）が分かっているときは、`PSN ID(キャラクター名)` の形で出します。** PSN ID だけだと、同じ名前の行が並んで見分けがつかなくなるためです。1 つのキャラクターしか分かっていない PSN ID は、PSN ID だけで出ます。どのキャラクターが同じ PSN ID かは、パーティー・照準・キルフィードで分かった分だけが対象です（分からないキャラクターは、キャラクター名で出ます）。
- 記録は今までどおりキャラクター名ごとです（キャラクターごとに 1 行になります）。同じキャラクター名の別人は、1 人にまとまります。
- 覚えた対応は、保存時に、記録に残っている名前の分だけに絞られます。1 回のプレイ中は 2000 人までです。
- `/hps status` に、覚えた人数と、その出どころ（パーティー・照準・キルフィード）が出ます。

### 記録する場所

初期値は **シロディールのみ**（帝都とバトルグラウンドは数えません）。設定で「すべての PvP ゾーン」「どこでも（PvE を含む）」に変えられます。

### 保存されるもの

アカウント単位で保存されます（キャラクターごとには分けません）。**直近 60 日**だけ保存し、それより古い日は起動時に消えます。1 日あたりの「回復した相手」は回復量の多い順に 60 人まで、「スキル」は 40 件までです。それを超えた分は、その日の合計（回復量・割合）には入ったまま、一覧からだけ外れます。

「記録をすべて消去」は確認ダイアログが出ます。

## 設定（設定 > アドオン > PB's HPS Checker）

| 項目 | 初期値 |
| --- | --- |

| HPS メーター：枠の大きさをpxで指定する | オフ（オンにすると、下の幅・高さの px のとおりの枠になる） |
| HPS メーター：枠の幅 / 高さ (px) | 600 / 220（オンのときだけ使う。5px 刻み） |
| HPS メーター：戦闘後に残す時間 | 10 秒（3〜60） |

## まだ実機で確かめていないこと

コンソールの実機では次の 4 点が未確認です。オフラインのテストでは確かめられないため、`/hps status` と `/hps debug` を用意しています。

1. **パーティー外のプレイヤーへの回復が、どの相手の種類で届くか。** このアドオンは「グループ = パーティー」「それ以外 = パーティー外」と読んでいます。`/hps status` の `target types:` に `GROUP=` `OTHER=` `PLAYER=` の件数が出ます。パーティー外の人を回復したのに `OTHER` が増えない場合は、読み方を直す必要があります。
2. **回復量にオーバーヒールが含まれているか。** 今は「`hitValue` は実際に回復した量、`overflow` は上限を超えた分」と読んでいます。`/hps debug` が `hit=` と `over=` を出すので、満タンの味方を回復して確かめられます。読み方は `Records.lua` の `records.ReadAmounts` 1 か所だけに書いてあります。

3. **他のヒーラーが行った回復が、パーティーメンバーへの分だけでもアドオンに届くか。** 「パーティーメンバーが受けた回復のうち自分の分」は、これが届く前提の機能です（パーティー外の人が受ける回復は、自分が行った分しか届かない見込みなので、割合は出せません）。届かない場合、割合は 100% のままになります（自分の分だけで数えるため）。`/hps probe` がそれを測ります。他のヒーラーが近くで回復している場面で `/hps probe` を打ち、2 分後に出る結果の行をそのまま送ってください。`パーティー外 > パーティーメンバー` と `パーティーメンバー > パーティーメンバー` が ○ なら働きます。`/hps status` の `others > party members:` の行でも、届いた件数を見られます。

4. **回復のイベントの相手の名前が、キャラクター名か、すでに PSN ID か。** 今は、キャラクター名として扱い、別の場所から PSN ID を覚えています（上の「名前の表示」）。`/hps debug` が出す `Alice^F` のような名前を見れば分かります。PSN ID がそのまま届いているなら、覚える仕組みは要らなくなります。

NPC（味方の衛兵など）に回復が当たった場合も、その名前で一覧に入ります。

## テスト

```
sh test/all.sh                    すべての組み合わせ（許可された 2 ID、日本語・英語・Lua 5.1、許可されない ID）
lua test/run.lua                  日本語クライアント、PinkBanther でログイン
LANGCODE=en lua test/run.lua      英語クライアント
PSNID=Yukiblack1123 lua test/run.lua   ログインする PSN ID を変える
PSNID=Someone lua test/run.lua    許可されない ID（何も作られないことだけを確かめる）
```

ESO の API の代わりを用意して、アドオンのファイルをマニフェストの順に読み込み、イベントを流して数字と画面の部品を確かめます（回復量の集計・戦闘の区切り・日付の切り替わり・一覧の整理・各画面・設定画面・コマンド・壊れた保存データ・PSN ID の照合）。ゲーム自体ではないので、フォントが作れるか、枠が描かれるか、回復が想定した相手の種類で届くかは、実機で確かめる必要があります。
