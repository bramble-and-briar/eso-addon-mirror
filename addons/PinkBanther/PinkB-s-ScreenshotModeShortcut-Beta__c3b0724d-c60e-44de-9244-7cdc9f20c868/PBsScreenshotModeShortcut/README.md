# PB's ScreenshotModeShortcut 1.1.1

ゲームパッドの通常画面で、**L2を押したまま十字キー左**を1回押すと、ESO標準のスクリーンショットモードを開始します。画像の撮影・保存はゲーム／本体側で行ってください。

**クイックショットモード（初期設定は無効）**を有効にすると、同じ同時押しでUIを数秒間（初期値5秒）だけ全部隠し、自動で元に戻します。スクリーンショットモードには入らないので、今やっていることを中断しません。**撮影はその間に本体のキャプチャーボタンで行ってください**（クライアントの撮影関数はアドオンからは呼べません。1.1.1参照）。設定画面またはコマンドで切り替えます。

**反応するのは十字キーの左だけです。** 左スティックを左へ倒している間の左入力は、アドオンは一切消費せずゲームへ返します（1.0.6）。

**戦闘中はL2＋左による起動と、モード内の納刀ショートカットは無効です。** 戦闘開始時に保留中の入力とアドオンの入力レイヤーを解除し、戦闘終了後に再び有効になります。既に開いている標準スクリーンショットモードは自動終了しません。

## 更新・操作

1. ZIPを展開し、ESOの`AddOns`内の`PBsScreenshotModeShortcut`フォルダを新しい版に置き換えます。
2. `/reloadui`または再ログインで、変更した`Bindings.xml`を読み直します。
3. ゲームパッドモードでメニューを閉じ、L2を押したまま十字キー左を押します。左を離す通知は起動条件にしません。
4. 起動後にL2と左をいったん離し、**十字キー左を改めて長押し**すると納刀します。L2を離して防御を解除してから操作してください。納刀済みなら何もしません。
5. 標準モードでは約3秒後にUIが消えます。画面の「終了」ボタンで案内を表示し、表示中にもう一度押すと終了します。

1.0.2でL2を継承したバインドが防御を妨げる報告を受け、1.0.3ではそのバインドとイベント処理を削除しました。アドオンはL2や防御アクションを登録・実行しません。すぐ防御を戻す必要がある場合は、更新前に`/pbshot off`でアドオンの入力レイヤーを解除できます。

L2の押し込み値を読み、半分以上なら同時押しと判定します。補助として`IsBlockActive()`で防御状態も読みます。**L2が防御に割り当てられた標準操作を前提**とし、防御を別キーに変更した場合はそのキーで防御中の左でも反応します。読み取りだけで、防御の開始・終了は操作しません。

左の通常操作はハンドラーが`false`を返す設計です。同時押しでは押下・解放を両方消費し、モード移動中も同じ入力レイヤーを保持します。実際のボタン配送と武器操作の抑制には実機確認が必要です。

## コマンド

`/pbss`も同じ意味です。

| コマンド | 動作 |
| --- | --- |
| `/pbshot` または `/pbshot status` | バージョン、入力回数、analog値、防御状態、判定元、左スティックX値と除外回数、最後の結果 |
| `/pbshot now` | 通常画面からモード開始を確認 |
| `/pbshot quick on` / `/pbshot quick off` | クイックショットモード（初期設定：無効） |
| `/pbshot hold 1\|3\|5\|10` | クイックショットでUIを隠す秒数（初期設定：5秒） |
| `/pbshot mode auto` | 標準モードを試し、失敗時はUI非表示（初期設定） |
| `/pbshot mode scene` | 標準モードのみ。失敗時は理由を表示 |
| `/pbshot mode gui` | UI非表示のみ。同じL2＋左で復帰 |
| `/pbshot binds` | 左と納刀の継承バインドを表示 |
| `/pbshot on` / `/pbshot off` | 有効／無効 |
| `/pbshot reset` | 設定を初期化 |
| `/pbshot help` | ヘルプ |

UI非表示の代替動作はカメラ・ネームプレートの動作が標準モードとは異なります。同じショートカット、`/pbshot now`、`/pbshot off`で復帰できます。メニュー移動・ロード・コントローラー切断でも代替UI非表示を解除します。

## 検証

`lua test/run.lua`で56件のローカルテストを実行します。L2／防御のバインドをXMLに登録していないこと、入力状態、解放通知欠落、押し込みAPIの欠落・エラー、防御状態による判定、画面遷移、UI復帰を検証しています。Lua構文・XML・配布ZIPも確認しています。

**1.0.5のモード内納刀はESO実機未確認です。** ローカルテストはゲームの入力配送を再現した保証ではありません。更新後は「L2単独で防御開始・解除」「左単独で武器操作」「L2＋左1回で起動」「モード中にL2を離して左長押しで納刀」「納刀後にもう一度長押ししても抜刀しない」を確認してください。起動しない場合は、同時押し直後の`/pbshot status`と`/pbshot now`の結果で入力側とモード開始側を切り分けます。

## 1.1.1の変更：実機で判明した2点の修正

**1. `TakeScreenshot()`はPS5では非公開関数でした。** 1.1.0で呼び出したところ、次のUIエラーが出ました。

```
Attempt to access a private function 'TakeScreenshot' from insecure code.
The callstack became untrusted 2 stack frame(s) from the top.
```

さらに重要な点として、**`pcall`で包んでいてもクライアントのUIエラー画面は出ます**。Lua側で握り潰せる類のエラーではありません。撮影しようとしてエラー画面が被さるのでは本末転倒なので、**呼び出しを削除しました**。アドオンからクライアントに撮影させる手段は他にありません（`BindKeyToAction`も非公開で、`TAKE_SCREENSHOT`アクションを発火させるAPIもありません）。

そのためクイックショットモードは「UIを一定時間消して、自動で戻す」機能になりました。撮影はその間に本体のキャプチャーボタンで行ってください。手で押す時間が要るので、隠す時間の選択肢を**1／3／5／10秒**に変更し、初期値を5秒にしました。保持中にもう一度同時押しすれば、待たずに戻ります。`EVENT_SCREENSHOT_SAVED`の購読は残してあり、万一クライアント側から保存が通知された場合は待たずにUIを戻します。

**2. 設定画面とメッセージが日本語になりませんでした。** 言語ファイルを`lang/ja.lua`という名前にし、中で`GetCVar("language.2") ~= "ja"`と比較していたためです。**ESOの日本語クライアントの言語コードは`ja`ではなく`jp`**で（クライアント本体の言語ファイルも`jp_client.lua`）、この条件は日本語環境でも常に真になり、英語のまま読み飛ばされていました。

ファイルを`lang/jp.lua`に改名し、マニフェストの指定を`lang/$(language).lua`に変えました。これはクライアントが言語に応じて展開するもので、他のPB'sアドオンと同じ書き方です。言語判定をファイル内で行う必要はなくなったので、条件そのものを削除しました。英語・日本語の文字列IDが過不足なく対応していることと、言語判定が残っていないことはテストで検証しています。

## 1.1.0の変更：クイックショットモード

設定画面（LibHarvensAddonSettingsがある場合）に「クイックショットモードを使う」を追加しました。`/pbshot quick on`でも同じです。**初期設定は無効**で、無効の間の動作は1.0.6と変わりません。

有効時、L2＋十字キー左は`SetGuiHidden("ingame", true)`でUIを隠し、保持時間が過ぎたら戻します（当初はこの間に`TakeScreenshot()`を呼んでいましたが、1.1.1で削除しました）。ロード画面・メニュー移動・コントローラー切断でも必ずUIを戻します。

設定画面には「ショートカットを有効にする」「同時押しで開くもの（標準モード／UI非表示）」「クイックショットモードを使う」「UIを隠す時間」「今すぐ試す」「設定を初期化」を並べています。LibHarvensAddonSettingsが無くても、すべて`/pbshot`から操作できます。

## 1.0.6の変更

十字キー左として継承したバインドは、左スティックを左へ倒したときにも届きます。ESOでは左スティックが同じ方向入力を代行し、ハンドラー側にどちらのキーかを示す情報は渡りません。そこで入力が届いた時点で`GetGamepadLeftStickX()`を読み、デッドゾーン補正後の値が-0.35以下であれば左スティック由来と判断して、押下・解放ともに消費せずゲームへ返します。十字キーを押してもスティックのX値は動かないため、通常の同時押しはこれまでどおり動作します。

スクリーンショットモード内の納刀（左長押し）にも同じ判定を入れました。モード内で左へ歩いても納刀しません。

副作用として、**左スティックを左へ倒して移動しながらの同時押しは無効**です。立ち止まって操作してください。スティックの値が読めない場合は中立として扱い、従来どおり動作します。`/pbshot status`の`stickX`と`stick ignored`で判定を確認できます。

## 1.0.5の変更

標準の`ScreenshotMode`入力レイヤー内に、`SHEATHE_WEAPON_TOGGLE`の割り当てを継承する納刀専用アクションを追加しました。長押しの判定はESOの通常の納刀バインドを使用します。標準設定では十字キー左長押しです。カスタム設定では納刀に割り当てたキーに従います。

この追加処理は標準スクリーンショットモード内だけで動作し、モードを閉じずに納刀を要求します。既に納刀済みなら抜刀しません。`gui`代替モードは通常画面のままなので、この専用処理の対象外です。実機で動かなければ、操作後の`/pbshot status`と`/pbshot binds`で納刀アクションの到達・割り当てを確認します。
