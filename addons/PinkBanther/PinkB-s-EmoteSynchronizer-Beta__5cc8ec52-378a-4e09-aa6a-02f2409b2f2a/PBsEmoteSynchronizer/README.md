# PB's Emote Synchronizer 0.1.0

グループのリーダーがエモートをすると、このアドオンを入れているメンバーも同じエモートをします。ESO(PS5/Xbox/PC)用です。

**リーダーを含む全員に、このアドオンと LibGroupBroadcast が必要です。** ゲームには「誰かがエモートを始めた」ことを知らせる仕組みがなく、他人のエモートは読めません。リーダー自身のアドオンが自分のエモートを検知して、グループに知らせます。

## 仕組み

1. エモート画面、ユーティリティホイール、`/dance` などのスラッシュコマンドは、どれもグローバル関数 `PlayEmoteByIndex` を呼びます。アドオンはこの関数の手前に小さな関数を置き、リーダーがエモートをしたらエモートIDをグループへ送ってから、本物の関数を呼びます。本物の呼び出しは、送信が失敗しても止まりません。
2. 送るのは番号(インデックス)ではなくエモートIDです。番号は持っているエモートや言語で人によって変わるので、受け取った側が `GetEmoteIndex` で自分の番号に直します。
3. メンバーは、送り主がリーダーで、戦闘中ではなく、そのエモートを持っているときだけ再生します。それ以外は見送り、`/emotesync status` に理由が数えられます。
4. 通信は LibGroupBroadcast(プロトコルID 464)です。

## 限界

- **同時にはなりません。** LibGroupBroadcast は、静かな状態からの最初の送信を500ms待ってから行い、その後もゲームが送信の間隔を空けます。メンバーはリーダーより最低でも約0.5秒遅れます。「リーダーの再生を遅らせる」を使うと、リーダー自身のエモートをその分だけ待たせて、全員が一緒に始まるようにできます。コンソールでの実際の遅れは、計測するまで分かりません。
- **止まる合図は送りません。** エモートが終わったことを知る方法がないため、止めるのは各自です(動けばエモートは解除されます)。
- リーダー以外のエモートには追従しません。対象を取るエモート(相手を見て行うもの)は、同期しても相手がずれます。
- アドオンはグローバル関数を差し替えるため、他のアドオンが同じ関数を差し替えていると、順番によって両方が連なって動きます。

## 設定とコマンド

設定画面(LibHarvensAddonSettings)から、有効・送信・追従・チャット通知・リーダーの待ち時間、通信の遅れの計測ができます。

| コマンド | 内容 |
| --- | --- |
| `/emotesync status` | 役割、通信の状態、送信・受信・再生・失敗の数、見送った理由 |
| `/emotesync ping` | このアドオンを入れているメンバー全員との往復時間を測る |
| `/emotesync lead <ms \| auto>` | リーダーの再生を遅らせる。`auto` は直近の往復時間の半分 |
| `/emotesync play <エモート名>` | アドオンからエモートを再生する(動作確認用。何も送りません) |
| `/emotesync probe` | `PlayEmoteByIndex` が制限されていないかゲームに問い合わせる |
| `/emotesync on` / `off` | 全体のオン・オフ |
| `/emotesync debug` | 送受信の記録をチャットに出す |

見送った理由: `off`(設定でオフ)、`notLeader`(送り主がリーダーではない)、`duplicate`(同じ連番)、`combat`(自分が戦闘中)、`sendCombat`(リーダーが戦闘中のため送らなかった)、`unknown`(自分のゲームにないエモート)、`locked`(持っていないエモート)。

## PS5で確認すること(1回に1つずつ)

実機で初めて分かることが3つあります。順番に進めてください。

1. **アドオンがエモートを再生できるか(1人で)。** `/emotesync probe` のあと、`/emotesync play dance`。
   - `probe` が `private false / protected false` と出て、`play` でキャラが踊れば、この方式が成り立ちます。
   - `play` でエラー画面が出たら、`PlayEmoteByIndex` はアドオンから呼べません。そのときはこの方式をやめて作り直します。
   - `probe` 自体がエラー画面になった場合も教えてください(`IsPrivateFunction` が使えないという情報になります)。
2. **リーダーの検知が効くか(2人)。** リーダーが普通にエモートをする(エモート画面、ホイール、`/dance` の3通りを1回ずつ)。メンバーが同じエモートをすれば成功です。メンバー側で `/emotesync status` の「受信」「再生」の数も見てください。
3. **どれだけ遅れるか。** メンバーかリーダーが `/emotesync ping` を打ち、返ってきた往復時間を教えてください。そのあと `/emotesync lead auto` で待ち時間を入れて、もう一度エモートを試します。

## 開発

```sh
sh test/all.sh        # lua と luajit の両方でオフラインテストを実行
```

テストは、複数のクライアントを同時に読み込み、LibGroupBroadcast のソースが行う待ち(500ms の待機、1秒の送信間隔、キューの置き換え、フィールドの範囲検査)を模した代用品でつなぎます。確かめられるのは論理だけで、実際の通信の遅れや、`PlayEmoteByIndex` を呼べるかどうかは、PS5での確認が要ります。
