# 英→日エンジン更新 — 1.3.0-dev

## 構成

Tokenizer → 辞書・活用照合 → 節の分割 → Semantic の構造解析 → 日本語生成、という処理を加えた。Semantic が扱わない文は従来の Grammar に渡す。既存の辞書・日→英エンジン・設定・共有プロトコルは維持する。

Semantic は主語・動作・対象・否定の範囲・時制・場所・時間を一時的な構造にする。資源不足、残数、門や壁の破壊、戦闘員の戦闘不能、必要な人員、他者への動作依頼、場所を尋ねる依頼を扱う。入力全体が読めた候補だけを比較し、競合したら既存処理に戻す。候補の点数は手作業の規則であり、統計的な正解確率ではない。機械学習モデルや外部APIは使わない。

ユーザー辞書に該当する語を含む文では、構造解析による意味の上書きを避ける。未知語・アイテムリンクは残す。一般文法側も否定、unless、受け身の進行形、完了の否定、句動詞、関係節、still、try の進行形を改善した。

| 英文 | 実際の出力 |
| --- | --- |
| out of magicka | マジカが尽きています |
| two enemies left | 敵×2が残っています |
| we do not need you to attack | 私たちはあなたに攻撃してもらう必要はありません |
| we need you not to attack | 私たちはあなたに攻撃しないようにしてもらう必要があります |
| I have not used my ultimate yet | 私はまだアルティメットを使っていません |
| I was trying to join | 私は参加しようとしていました |

## メモリと入力制限

- 英→日の入力は4,096バイト・256トークンまで。超過時は原文をそのまま返す。構造解析は64項目まで。
- ユーザー辞書は2,000枠。日→英の活用展開を考慮して、動詞は12枠、形容詞は6枠、その他は1枠を使う。全て名詞なら2,000件。
- 登録キーと値の合計128 KiBまで。キーは192バイト、値は768バイトまで。バイト数は日本語の文字数とは異なる。
- 手動追加・共有辞書の取り込み・バックアップ復元は上限を事前確認し、超過なら保存状態を変更しない。
- 既存の保存済み辞書が上限を超えていた場合、データは削除しないが、その辞書のコンパイルを中止して通知する。適用するには登録数・文字列量を減らす必要がある。
- 通常の翻訳時はGCの段階的な回収を進める。日→英の逆引き索引の再構築後は、古い索引を解放するため完全回収を実行する。GCのグローバル設定値は変更しない。
- ゲーム側でGC呼び出しが許可されない場合は明示的回収を無効にし、翻訳自体は継続する。その場合のピークは今回の測定値と異なる可能性がある。

## 検証結果

Lua 5.4 / LuaJIT のそれぞれで、run、accuracy、chat_precision、grammar_precision、slang、slangnet、ja_en、outgoing、sharing、sharing_ui、sharing_interact、refresh、dict_check、memory を実行し、全て成功した。辞書9,232項目、エラー0件、既存警告7件。

追加した83例を通常・大文字、シロディール内外で検証した。未知語、リンク、ユーザー辞書優先、入力制限、辞書容量の検証を合わせ360チェック成功。今回選定した83例の通常条件では、旧1.2.2-devの完全一致31例に対し、新版は83例一致した。この集合は改善対象と反例から作った回帰テストであり、無作為な実チャットの精度評価ではない。

`test/memory.lua` はアドオン全体をゲームAPIの代替環境でロードし、両方向翻訳、名詞2,000件、重み付き上限の動詞辞書、2,000回の翻訳、索引再構築を測定する。GCを停止せず、1,000 VM命令ごとと処理境界でサンプリングした。空のテストプロセスからのLua管理メモリ増分である。

| 実行環境 | 回収後の増分 | サンプリングしたピーク |
| --- | ---: | ---: |
| Lua 5.4 | 5,422,956バイト | 8,313,904バイト |
| LuaJIT | 5,943,058バイト | 7,639,806バイト |

10 MBを10,000,000バイトとして検査している。これはESO全体のメモリではなく、全入力での厳密な最大値の保証でもない。実機では他のアドオン、保存済みデータ量、共有時の一時データ、Luaランタイムに依存する。索引再構築の完全GCは共有VMにも作用し、一時的にフレームを止める可能性がある。実機でのメモリ・フレーム時間は未確認。

## 再実行

アドオンディレクトリから `lua test/refresh.lua` と `lua test/memory.lua` を実行する。LuaJITでは先頭を `luajit` に置き換える。既存の各 `test/*.lua` のテストランナーも同様に実行できる。

未対応の構文や曖昧な指示は残る。複雑な入れ子、文脈依存の主語省略、未知の人名、皮肉などを一般的に解決するものではない。実チャットの誤訳例を回帰テストに加えながら改善できる構成にした。

## 1.3.2-dev の日本語生成改善

単独の自己報告の「私は」を省略し、条件・疑問・対比・強調では残す。「I heal too」は「私も回復します」とする。自分・自分たちから相手への現在の直接的な依頼だけを「〜してほしいです」とし、否定された必要性や過去の必要性、第三者の行動は区別する。残数・募集の構造解析に、人物・役割の「人」、ポーションの「本」、魂石の「個」、一部攻城兵器の「台」を追加した。他の構文の数量表記には「×」が残る。

`test/natural.lua` は30例を大文字小文字・シロディール内外で検証し、ユーザー辞書・リンク・未知語の保全を合わせ125チェック。旧テストの期待値は意図した主語省略・依頼表現・数量表現を確認して更新した。今回の変更をもって翻訳精度が何％向上したと評価するものではない。

今回の負荷試験のピーク増分はLua 5.4で8,314,821バイト、LuaJITで7,675,325バイト。測定条件と実機未確認の制約は上記と同じ。
