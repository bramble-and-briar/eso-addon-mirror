Start here

SmartChatMsg prepares reusable announcements in ESO chat. You press Enter to send. It can prepare messages on demand, at startup, on zone arrival, or during scheduled promotion periods. It runs only while ESO is open and the addon is loaded; it cannot post while you are offline. Version 3.01 targets ESO API 101051. Required libraries: LibAddonMenu-2.0 version 34 or newer and LibAddonMenuDatePicker. Sliders are included in LibAddonMenu; no separate slider library is required. LibDebugLogger is optional.

Install, update, and back up

Extract the SmartChatMsg folder into your ESO live/AddOns directory and enable the addon and required libraries. Keep a backup of your current live/SavedVariables/SmartChatMsg.lua before replacing or editing it. Do not overwrite SavedVariables while ESO is running: the game can replace your changes when it exits. Open /scm for settings. If you are starting fresh, create a command, select its guild, choose an output channel, and add at least one message. One command can have different messages and settings for different guilds. Existing older schedule formats are not supported by this release; ordinary message content should be backed up before updating. The applications do not automatically convert old schedules.

Optional companion: SmartChatMsg-Web

For a larger editor and visual planning tools, visit https://scm.perdues.me. Install SmartChatMsg and run ESO with the addon enabled at least once, then exit ESO fully so it writes live/SavedVariables/SmartChatMsg.lua. Open that file in the companion app; it supplies your account and saved guild/configuration information. The web companion provides period editing, message libraries, previews, a schedule overview, and a draggable day view. You can also configure schedules directly in ESO. Download the updated Lua file, keep a backup, and install it as SmartChatMsg.lua in SavedVariables while ESO is closed. A browser download does not itself update your ESO installation. The addon still handles live chat detection and message preparation. The optional server library can save a full configuration or an event export containing selected events or all events. Event exports include their messages and delivery settings, including Use condensed dates and times. Load your own SavedVariables file first when merging shared events. Review and select the events to import; matching uses guild name and command name rather than the sender's guild slot or internal IDs. Unrelated local settings and recipient runtime history are preserved. Review each matching event because its imported configuration can update your existing event.

Server-library records remain readable without a password. When saving a record, you may set an optional overwrite password to protect later replacement of that record. Overwriting a protected record requires password confirmation. The server stores a hash of the secret, and the password is not an ESO addon setting or a SavedVariables feature. Read access is not restricted by an overwrite password. Downloading a configuration includes your applied edits; review the target account and guild before installing.

Commands, guilds, channels, and message pools

Create a short command name such as recruit or tours. Under Create / Edit / Delete Messages, select the command and guild, then choose Guild, Officer, Zone, or Group. Group chat uses /g; Guild and Officer chat use the selected guild's current slot. The guild remains the configuration identity even when output goes to Zone or Group. Enter a message and click Add. Update and Delete edit existing messages. Add several alternatives for a varied pool: selection is randomized with usage weighting. Keep the final expanded announcement under 350 characters; substitutions can make the output longer than its template. Use Test to view parsed output in your own chat without posting it. For On Demand and Startup, only enabled messages are eligible for selection. Disabling one removes it from your outgoing pool without deleting its content; incoming duplicate monitoring is separate. For Scheduled, choose eligible messages separately for each period. A period needs at least one suitable message to deliver an announcement.

Global settings and timezones

Default guild is used by ordinary slash commands when you omit a guild argument. Auto-Remove Pending Chat After uses a slider from 30 to 300 seconds, with exact seconds entry. It is the timeout for an unsent prepared message; player-edited chat is protected. The default scheduling timezone can be ET, CT, MT, or PT. Each guild can override it under Scheduling > Guild timezone. US daylight-saving rules are calculated for the event date. Mountain follows DST-observing Mountain time. All scheduling dates and clocks use the effective guild scheduling timezone, independently of your computer timezone. Changing the default timezone keeps the entered calendar dates and clock times for guilds using that default, changing their UTC moments. Explicit guild overrides stay in effect. Changing a guild timezone moves that guild's schedules to the same clock time in the selected zone. Literal timezone text in messages is not rewritten; prefer event substitutions. The missing spring clock hour is invalid. Repeated autumn clock hours use the configured fold choice where available; avoid ambiguous hours when possible.

Run At: On Demand, Startup, or Scheduled

On Demand waits for your custom command, for example /recruit 1. The optional number identifies the guild slot; without it the configured default is used. It can prepare one message or engage timed repetition. Startup engages ordinary delivery when the addon initializes, including UI reload. Its custom command remains available. This is useful for ordinary repeating or zone-arrival workflows. Scheduled uses the event and Period Timeline instead. Save and activate engages it automatically when its times are eligible. You do not need to launch a custom command. A command used only by scheduled combinations does not register its own slash command; switching it to On Demand or Startup restores ordinary command use.

Ordinary delivery controls

Repeat Frequency: Off means no timed repeat; otherwise it controls the interval for ordinary repeated messages. The slider covers Off through 1440 minutes. Retry Delay: after an unsent repeated message times out, this controls when to try again. Off uses the normal repeat behavior. Its slider covers Off through 60 minutes, capped by the smaller positive Repeat Frequency and Cooldown. Retry is unavailable without timed repetition. Auto Populate Chat on Zone prepares a message when you enter an eligible parent zone. This replaces ordinary timed repetition, so Repeat Frequency is disabled while it is enabled. Cooldown is the automatic zone cooldown; its slider covers 15–480 minutes. Existing values outside slider ranges are retained until deliberately changed. Exact-minute entry remains available. Open Status Panel on Run is available for On Demand, Startup and Scheduled combinations. It shows the status window when the command runs or when scheduled promotion becomes active; closing the panel does not disable the command. Notify Sound selects the preparation sound; Preview plays it in ESO and None is silent. These settings belong to the selected command and guild.

Build an event and its Period Timeline

Set Run At to Scheduled and open Scheduling. Under Event date and time, select the actual event date and time. This is the event itself, not when advertising starts. Set Event duration if it continues after its start. Duration 0 displays Not set. Choose recurrence and any special pattern, then configure Period Timeline. Add a period, give it a Period Label, and set Period Starts and Period Stops using calendars and hour/minute/AM-PM controls. Dates displayed are based on an event occurrence; the saved relationships follow recurring events. Set Repeat Frequency and check the message pool for that period. Use different periods to change frequency and wording without creating separate commands. Period Status can enable, pause, or disable the period while keeping its content. Normal promotion begins on or before the event. Enable Allow promotion after event starts for underway invitations; this control requires a positive event duration. Delivery is capped by the event end unless the closing exception applies. The web editor orders periods chronologically and flags overlapping ordinary windows; adjacent windows can meet at the same boundary. Preview Period Timeline in ESO and click message text to test it at a simulated time in the selected period. Save and activate commits and enables the schedule; Save disabled retains it without running.

Example: an 8 PM event lasting two hours

Set Event Start Time to 8 PM and duration to 120 minutes. Create an early-promotion period from the previous evening to 6 PM with a four-hour frequency. Create a final-promotion period from 6 PM to 8 PM with a 30-minute frequency and more urgent messages. Add a Send once, time-sensitive notice at 8 PM: “We are starting!” Then create an underway period from 8 PM to 10 PM, enable Allow promotion after event starts, and select “come join us” messages. Keep the end at 10 PM so invitations stop when the activity is over. Use separate message selections for these periods. A starting notice should not share wording intended for several days before the event.

Send once, time-sensitive notices, and closing announcements

Send once means one confirmed announcement for that period and event occurrence. It does not repeat when its frequency comes around. A matching announcement from someone else can also complete it. Preparing chat alone does not complete it. A future event occurrence starts fresh. Lateness allowance defines the short opportunity after a one-time notice becomes due. If the window passes while you are offline, the expired notice is skipped. Send once anytime in this period allows that one announcement during its full configured window instead of only the short grace. Time-sensitive notices can bypass ordinary inter-schedule pacing, but still respect startup protection, chat safety, eligibility, duplicate suppression, and daily limits. They prepare chat; they do not automatically press Enter. Allow a closing announcement after the event ends is an advanced exception for notices such as “The auction is closed.” It permits the selected period beyond the duration cap. Keep its own stop/grace short and usually enable Send once. It is different from ordinary invitations while an event is still running.

Availability and daily announcement limits

Availability restricts announcement weekdays and server-clock hours inside a period. These are advertising days, not the event's recurrence weekdays. An overnight window belongs to its opening date. Weekday and exact-date hour overrides can change particular windows; exact-date overrides take priority, and Reset removes the selected override. Daily announcement limit is outside Availability and works even when hour restrictions are off. Slider 0 displays Unlimited; the slider goes through 20. Unchecked Share Limit to ALL periods means a separate daily maximum for this period. Checked shares one maximum across every period for the same command and guild. All selected messages count toward the same applicable limit; it is not a limit per template. Confirmed sends and recognized matching announcements from other players count. Preparing, timing out, and retrying do not consume a send. Counts persist through reload/logout and reset at midnight in the scheduling timezone. Switching scope does not intentionally reset today's history. Status distinguishes Period daily limit reached from Command daily limit reached and shows the count/maximum. /scm resetcooldowns also clears daily usage. Use it for testing, not to preserve a daily cap. Portable configuration exports do not copy another player's usage counters; recipient usage is retained where records match.

Recurrence and special patterns

Choose once, daily, weekly, every other week, monthly on date, or monthly on weekday. The original event date anchors the repeat pattern; the next occurrence is calculated automatically. Recurrence interval multiplies that unit. For the last Sunday of every month, use monthly on weekday, Last, Sunday. Repeat on weekdays selects actual event occurrence days. It does not prevent advertising on other days: use Availability for advertising restrictions. Leave optional weekday overrides unset to follow the event date's weekday. Last event of month selects the final occurrence of the recurring pattern in that calendar month. Messages can use Regular, Month-final, or All events groups. If no month-final alternatives are configured, regular messages provide the fallback. Faction rotation uses an ordered selection of factions and a number of weeks per faction. The event itself can still run weekly. AD means Aldmeri Dominion, EP means Ebonheart Pact, and DC means Daggerfall Covenant. Use %eventfaction% to insert the selected faction's full name. Rotating event uses an ordered list of named activities and a number of occurrences per activity. Use %eventactivity% for the selected activity. Event Date anchors the first entry. Cancellation can Keep rotation (consume its place) or Postpone rotation (hold its place); undoing the cancellation recalculates later selections. Exceptions are stored with the schedule, so ESO does not need a remote database.

Important times and message substitutions

Important times names a moment such as gathering or ticket sales close. Add one, choose its date and time in the scheduling timezone, and use the substitution key displayed in settings. The editor stores its offset from the event, so it follows recurring events. Example: an 8 PM event with a 7 PM tickets deadline stores one hour before the event. General tokens: %timeofday% (morning, afternoon, or evening), %guild% (resolved guild), and %zone% (current zone). Older greeting aliases remain recognized, but only one general time-of-day choice is needed in an insert menu. Tokens are case-insensitive. Scheduled tokens: %eventwhen% gives a human-readable day reference; %eventdate% gives the event date; %eventtime% gives its clock time with timezone; %eventcountdown% gives time remaining. %eventfaction% and %eventactivity% use the corresponding special pattern. Adjustable offsets include %eventwhen-1h%, %eventdate-1h%, %eventtime-1h%, and %eventcountdown-1h%. You can use other supported offsets such as -2h or -1d. Named moments use %eventwhen:tickets%, %eventdate:tickets%, %eventtime:tickets%, and %eventcountdown:tickets%, where tickets is the displayed key. Test before using them; a deadline already in the past should not be advertised as still open. Example template: “Family business: raffle %eventwhen% at %eventtime% (%eventcountdown%). Tickets close %eventwhen-1h% at %eventtime-1h% (%eventcountdown-1h%).” Use a different period after ticket sales close so it no longer invites purchases. Ordinary commands have no scheduled event context. Use general tokens there. Recognized literal date/time text can receive a calculated countdown; it does not create an event schedule. Preview the final message to check its meaning and expanded length.

Condensed dates and times (3.01)

Enable Use condensed dates and times for the selected command and guild in the original settings or the custom planner's Event/Command settings. It defaults to off, so existing messages keep their standard formatting. The setting is saved independently for each command/guild combination and travels with configuration and event exports.

With it enabled, %eventdate% uses MM/DD, such as 11/03; %eventtime% uses 8PM ET or 645PM ET, omitting zero minutes and spaces within the clock. %eventwhen% keeps relative words such as today/tomorrow and shortens weekday/date references. Offsets and named important-time forms use the same choice. It changes generated substitutions rather than literal date/time text you typed. Preview the expanded message before sending.

Duplicate monitoring recognizes both standard and condensed generated date/time wording, regardless of your own selected output style. Countdown differences and supported dynamic tokens continue to be recognized. An abbreviated date does not alter the event's saved date, timezone, or schedule.

Duplicate detection, cooldowns, and chat safety

Other players' matching announcements update your command/guild cooldowns even when you have not engaged that command. Guild and Officer matches require the correct guild and channel; Zone requires Zone and Group requires Group. Your own incoming messages are excluded from peer detection. Matching understands supported substitutions and generated countdown differences, so changing remaining time does not prevent a match. Fixed text is normalized, with conservative spelling tolerance for sufficiently long messages. This is not unrestricted semantic matching: numbers, guild identities and other protected content are not casually ignored. A recognized peer announcement adds the existing randomized 30–90 seconds to help separate clients. Scheduled automation waits three minutes after startup. An ordinary scheduled send pauses other scheduled commands for five minutes; the same command can use a shorter configured interval. Multiple eligible schedules are randomized. Time-sensitive notices have the pacing exception described above. A busy chat draft is protected. SmartChatMsg prepares an announcement only when eligible and safe; sounds and local notifications help you notice it. Start, end, period-change and skip messages explain schedule activity. Cooldown/status changes can come from another player's announcement, not only your own sends.

Status window, testing, and recovery commands

/scm opens settings. /scm schedule opens the custom Event Planner. /scm status toggles the status panel. /scm retry restores the latest eligible unsent message from the current UI session, including a pending message still protected by its timeout watcher. You do not have to wait for timeout. Player-edited drafts must be cleared first; normal eligibility and peer cooldown rules remain in effect. /scm resetcooldowns clears stored cooldown/testing history, including daily counts. /scmdebug on and /scmdebug off control debugging. /scm send <name> [guild number] requests an extra scheduled message, for example /scm send tours 1. It uses the currently eligible period/pool and normal substitutions. Eligibility, safety, peer suppression and applicable limits still apply; it does not enable a disabled schedule or make an expired period active. Only a confirmed send records a send. The status panel groups Auto and Repeat Commands, with collapsible sections. Cards identify Scheduled or On Demand, show activity/state, promotion range, selected period/frequency and sending information. Enable/Disable affects that card's command and guild. Active cards sort first, so disabling may move a card. Next Send is shown only for active entries; a due timestamp includes a countdown and clock time with seconds when applicable. To test safely, create a short event a few minutes ahead, use a small message pool, and preview each period. Remember the startup delay, any existing daily limit and peer cooldown. Do not expect chat to be posted without Enter. If nothing prepares, inspect status for no eligible messages, a future window, protected chat, startup delay, spacing or a reached limit.

Import, export, and saved files

ESO Import / Export Settings now merges instead of replacing your collections. Commands match by normalized name and guild; messages match by stable ID first, then exact text (and scheduled message group). Local IDs, usage, cooldowns and omitted commands/messages are retained. New records are added; importing the same records again does not duplicate them. Message names are descriptions, not identity keys. If a message has both a different ID and different text, it is treated as new. A matching event receives the imported timeline and delivery settings, so omitted local message text remains saved but is not automatically added to the imported period pools. Back up before importing and review the updated event settings.

Web event exports are selective JSON bundles; native ESO exports use SCM_EXPORT text. These transfer formats are not interchangeable. The SavedVariables Lua file is the common configuration file for the addon and web editor. Loading or replacing a whole Lua file is separate from merging an export.

Use Import / Export Settings for portable configuration. Guild references are exported by name and resolved to the receiving player's current guild slots. Missing guild records are skipped with a local explanation. Matching command names are reconciled even if IDs differ. Review the import result before enabling automation. Configuration includes command/guild delivery settings, messages, schedules, periods, important times, recurrence, rotations and exceptions, availability, daily-limit scope, and condensed date/time formatting. Portable transfers preserve recipient cooldown/usage history rather than adopting another player's runtime counters. Full SavedVariables files contain account-specific data; choose the correct account when editing them in the web companion. The Lock button is not exposed in the ESO editor. Existing personal/locked metadata is still respected by transfer code; do not assume a full Lua backup or public server-library file hides private content. Keep backups before any replacement. In ESO, Message name (optional) identifies a template in settings and pools, up to 60 characters, and is never sent in chat. Use Add for a new message or Update/Revert for existing name/text changes. A live right-aligned count such as 123/350 appears below each message box; it counts template characters before substitutions and flags values above 350. Test the final expanded output as well. The web editor also provides drag-and-drop message ordering.

Context-sensitive settings

In the ESO settings, Scheduled hides ordinary Repeat Frequency, Retry Delay, Cooldown and Auto Populate Chat on Zone controls; periods provide their own timing. Editable submenus open when you load a command/guild or when they become relevant, and unavailable or read-only sections close. Your manual collapse is retained until the section becomes relevant again or you select a different command/guild. Hover over period flags and timing controls for explanations.

Scheduled sending switch

Use /scm off to suspend scheduled sending for this account. The setting is saved across reload/logout. Incoming duplicate monitoring continues, and ordinary On Demand, Startup and Auto Populate Chat on Zone remain available. Untouched pending scheduled messages and queued scheduled requests are withdrawn; edited player text is preserved. /scm on resumes currently eligible scheduled periods without bypassing startup delay, cooldowns or expired one-time notices. The status header shows Scheduled sending: OFF and, while applicable, a countdown of the five-minute wait for other scheduled commands. Startup reminds you how to re-enable schedules when the saved switch is off. Built-in names on, off, schedule, status, retry, resetcooldowns, send, scm and scmdebug cannot be created, renamed to or imported as custom commands.

Custom ESO Event Planner

Open /scm schedule or choose Open Event Planner (new window) in /scm. This optional native ESO window uses the same commands, guild settings, messages and Period Timeline data as the original settings and the web companion. /scm still opens the original settings.

  • Choose the guild and output channel across the top. All displayed scheduling clocks use that guild’s scheduling timezone.
  • The left column lists commands/events. Search by name, select one, or choose + Event. New entries default to On Demand. New command names accept 1–25 letters/numbers; reserved names are rejected.
  • Scheduled entries show all their periods in the middle column. Scroll this list independently and click a period to select it. + Period adds another private draft. Selection uses stable IDs, so editing/sorting does not select a different period accidentally.
  • Event settings contains Run at, event date, event time, recurrence, duration, upcoming dates, status-panel preference and notification sound. On Demand/Startup instead show their ordinary delivery controls; zone population disables Repeat Frequency.
  • Period settings edits the selected period’s label, calendar dates and server clocks, frequency or one-time delivery, time sensitivity, closing exception, daily-limit scope, allowed weekdays/hours, and message pool. Period timing follows future event occurrences. Saving rejects overlapping enabled repeating periods and identifies their labels; one-time notices can coincide with a regular period.
  • Message library edits optional names and templates, shows a live character count, adds/removes messages, and controls ordinary command pool enablement. Removing a message also removes its references from this event’s period pools.
  • Test renders the selected template with substitutions. For Scheduled it simulates a time inside the selected period; ordinary messages use the real current time. The result appears in the preview and in local notification chat. Testing never prepares an outgoing announcement or consumes a cooldown.

Save changes saves the selected command/guild configuration. Edits are private until saved. It retains current cooldowns, send history and peer-observation counters, including updates that happened while the window was open. Empty message templates and invalid schedule inputs are rejected. Changing event/guild or closing with Cancel asks before discarding unsaved edits. Escape hides the window while retaining its unsaved draft for reopening.

Drag the title to move the window; use its resize grip to resize. Position and dimensions are saved per account. Small displays use independent scrolling panes.

Global settings opens account defaults: default guild, default scheduling timezone, and the chat-clearing timeout. Guild settings changes the selected guild timezone or follows the global default. Advanced configures monthly rules, recurrence weekdays, rotations, cancellations and named important times. Period includes weekday/date availability overrides and resets; Messages includes message groups and individual Apply/Revert. Import / Export is available directly in the left column. Existing settings remains an optional alternate interface; none of these settings requires it. No new library dependency or SavedVariables schedule format is required.

Planner visual indicators and controls

The custom planner uses a charcoal/blue palette, warm white native fonts, muted gold for the selected item and primary actions, and teal for period frequency. Buttons center their labels horizontally and vertically. Checkboxes use ESO’s native checkbox widget; sliders have a narrow visible track and larger native thumb. No additional dependency is needed.

A gold-tinted period card is the period selected for editing. A green indicator marks the currently active saved period, independently of the selected private draft. It updates once per second without rebuilding the editor, changing focus or resetting scroll. Hover over the indicator for an explanation. A green indicator does not mean a send is immediate: global sending state, startup delay, cooldowns, daily limits and chat protection still apply.

Each card shows its name, Starts, Stops, and frequency in separate controls. Frequency has its own row beneath a divider. Heights are measured so wrapped dates/names do not consume the frequency row. One-time notices say Send once and do not invent an end time.

Complete settings in the custom planner

The custom window exposes the configuration controls described below from the original settings. See ESO-Planner-Settings-Parity.md for the control-by-control audit. The 3.01 date/time formatting choice is also available in Event/Command settings.

Use the left Global settings button for default guild, default timezone and Auto-remove pending chat after (30 seconds to 5 minutes, slider or exact entry). This is separate from the top Guild selector, which only chooses what you are editing. The top Guild settings button edits that guild’s timezone override.

The Advanced tab contains monthly weekday rules, recurrence weekday filters, faction/activity rotations, occurrence cancellation and undo, and named important-time calendars/clocks and tokens. Period includes after-start permission, pause, closing notices, once/late options, limits, allowed hours and weekday/date overrides with Reset. Messages exposes template groups, membership, individual Apply and Revert, and enablement. Apply saves that template only; Save changes applies the rest of the event draft. Renaming and deleting commands are available in Event/Command settings; deletion confirms its effect on every guild.

The native Import / Export dialog uses the same guild-name matching and merge rules as the original settings. Export reads saved settings; pending drafts must first be saved. Import confirms before applying. Global/guild dialogs and imports refresh the selected event afterward so it cannot later save a stale schedule reference.

Sliders include exact-number entry. Invalid or out-of-range values are not saved. The planner also opens without guild membership for global settings and command management; a guild is required for messages and scheduling.

Copying an export

In the planner Import / Export dialog, click Export. The text field automatically takes keyboard focus and selects the entire export, including offscreen lines. Press Ctrl+C to copy it. Select all repeats the focus-and-select action if you clicked elsewhere. Paste with Ctrl+V. Clicking inside the text also focuses it normally; copy/paste and multiline cursor scrolling are enabled.

Live eligibility in period cards

The active saved period card shows Next eligible between Stops and frequency. Its elapsed countdown updates every second and uses this command/guild’s actual scheduled deadline, including observed-message cooldowns, startup delay and spacing between other scheduled commands. It does not use unsaved period edits. When applicable it instead shows Ready now, a prepared-message prompt, waiting for chat/zone arrival, sending off, the period/command daily limit, or no further send before this period ends. Eligibility is not automatic transmission: press Enter when a message is prepared.

Phase changes reflow only the period list, preserving its scroll anchor; ticking the countdown does not rebuild the editor or interrupt typing. The green dot still marks the active saved period and the gold card marks your editing selection.

Guild settings uses its own centered dialog container. Saving or cancelling hides the dialog without moving the launch button or leaving dialog fields attached to it.

Explicit %eventcountdown% substitutions (including offsets and named important times) show days, hours, and minutes without coarse rounding. For example, 10d 6h 17m becomes 10d 5h 17m with %eventcountdown-1h%. Positive durations round up only to the next minute; deadlines show now or passed when reached. Automatically inserted countdowns retain their approximate display.
